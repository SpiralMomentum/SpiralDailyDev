# 인생잔고 (life_balance) 설계 문서

- 작성일: 2026-11-25
- 원본 기획서: `doc/26_Q4/인생잔고_기획서.md` (v0.1)
- 대상 플랫폼: Android (Google Play) 첫 출시. iOS는 이번 범위 밖.

## 1. 의도와 이유

기대여명에서 역산한 남은 삶을 은행 잔고처럼 보여주는 위젯 중심 앱이다. 후속 메멘토 모리 앱 '카이로스'의 남은 삶 위젯을 먼저 단독 제품으로 떼어내 사용자를 모으고, 카이로스 출시 때 이전시키는 연결 고리 역할을 한다. 핵심 가치는 앱 화면이 아니라 홈 화면 위젯과 상시 알림에서 전달되므로, 앱을 다시 열지 않아도 숫자가 매일 정확해야 한다.

## 2. 목표 / 비목표 / 실패 조건

목표 (기획서 4장 전체, Android)
- 온보딩 1분 이내: 생년월일, 성별, 국가 입력 후 즉시 첫 잔고 표시와 위젯 추가 안내
- 생명표 기반 잔고 계산, 표시 단위 4종(일/주/년/백분율), 보너스 잔고
- 홈 화면 위젯 소형/중형 (Glance)
- Android 상시(ongoing) 알림, 기본 켜짐, 자정 갱신
- 말투 3종(스토아/위트/커뮤니티)과 말투별 테마(색, 폰트), 라이트/다크
- 설정 화면, 카이로스 소개 영역

비목표
- iOS 빌드, WidgetKit, 라이브 액티비티
- 거래 명세(지나온 날 기록) — 기획서 3장 선택 기능, 로드맵 2단계
- 광고 SDK — 이후 업데이트
- 서버, 계정, 네트워크 통신 일체
- 카이로스 데이터 이전 연동 (3단계)
- Android 잠금 화면 위젯: Android 폰은 5.0 이후 잠금 화면 위젯을 지원하지 않으므로 상시 알림이 그 역할을 대신한다

실패 조건 (동작해도 실패로 본다)
- 앱을 며칠 열지 않았을 때 위젯 숫자가 실제 남은 일수와 다름
- 자정이 지나도 위젯/알림이 전날 값에 머묾 (위젯은 허용 오차 0일, 알림은 OS 지연 범위 내)
- 잔고 숫자 자릿수 폭이 날마다 흔들림
- 커뮤니티 말투에 Play 정책 위반(혐오, 차별) 표현 포함
- 기대 수명 데이터 출처를 원문으로 확인할 수 없음

## 3. 제약

- 모노레포 `apps/life_balance`, 패키지명/applicationId `com.spiralmomentum.life_balance`
- Flutter 3.41.2 / Dart 3.11.0. 기존 앱 구조(`doc/Coding/Architecture/structure_strategy.md`)를 따른다: `lib/app`, `lib/features/<feature>/{data,domain,presentation}`, flutter_bloc, get_it, 테스트는 mocktail (build_runner 사용 불가 환경)
- 함수는 순수 함수/불변 데이터 우선, 부수효과는 data 계층과 플랫폼 경계로 분리
- 모든 데이터는 기기 로컬. 네트워크 권한을 쓰지 않는다 (카이로스 외부 링크는 브라우저로 위임)
- 리서치로 얻은 사실(생명표 수치, GDP 순위, 폰트 라이선스)은 원문 URL과 대조한 근거를 남긴다

## 4. 접근 방식 (검토한 대안)

생명표 데이터 확보 방법에서 세 가지를 검토했다.

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 11개국 모두 WHO 생명표 | 단일 출처, 동일 형식 | 최신 연도가 2~3년 늦고 5세 구간이라 보간 필요 |
| B | 11개국 각국 통계청 완전생명표 | 국가별 최신, 1세 단위 | 형식/연도/언어 제각각, 수집·검증 비용 수 배 |
| **C (선택)** | 한국은 통계청 완전생명표, 나머지 10개국은 WHO | 주 사용자(한국) 정확도 확보, 비용은 A 수준 | 출처가 둘이라 메타데이터에 국가별 출처 표기 필요 |

사용자가 C를 선택했다. 국가 목록은 IMF 명목 GDP 상위 10개국(구현 시 최신 WEO 원문으로 확정, 현재 파악은 미국, 중국, 독일, 일본, 인도, 영국, 프랑스, 이탈리아, 캐나다, 브라질)에 한국을 추가한 11개국이다.

위젯 갱신 구조는 대안 없이 다음으로 정했다(설계자 판단): 위젯이 매 렌더마다 오늘 날짜와 저장된 만기일 일정으로 남은 일수를 직접 계산한다. 자정 갱신 작업이 늦거나 누락되어도 다음 렌더에서 숫자가 맞는다. WorkManager에만 의존하는 방식은 Doze/제조사 배터리 정책으로 지연될 수 있어 배제했다.

## 5. 결정된 설계

### 5.1 기능 구성 (features)

- `life_table`: 생명표 에셋 로딩, (국가, 성별, 나이) → 기대여명 조회
- `balance`: 잔고 계산(순수 함수), 만기일 일정 생성, 메인 통장 화면
- `profile`: 생년월일/성별/국가/기대수명 수동값 저장, 온보딩
- `tone`: 말투 문구 테이블 로딩, 문구 렌더링, 말투별 테마
- `widget_sync`: home_widget으로 위젯 데이터 기록, 위젯 갱신 요청
- `ongoing_notification`: 상시 알림 표시/해제, WorkManager 자정 작업
- `settings`: 설정 화면
- `kairos`: 카이로스 소개 영역

### 5.2 생명표 데이터

- 에셋: `assets/life_tables/life_tables.json` 하나에 11개국 포함
- 스키마(안): `{ "version": "2026.11", "countries": { "KR": { "source": {"name", "url", "year"}, "male": [e0, e1, ..., e100], "female": [...] }, ... } }` — 0~100세 1세 단위 기대여명(년, 소수 2자리)
- 한국: 통계청 최신 완전생명표(0~100세 1세 단위)를 그대로 사용
- WHO 연도: WHO가 공개한 최신 연도를 쓴다(사용자 결정). 코로나 영향 연도일 수 있으나 '공식 통계 최신값' 원칙을 우선한다. 사용 연도는 SOURCES.md와 설정 화면 출처 표기에 명시
- WHO 국가: WHO GHO 생명표의 연령구간 시작 나이별 기대여명(ex)을 1세 단위로 선형 보간한다. WHO는 85+를 한 구간으로 주므로 86~100세는 한국 완전생명표의 85~100세 곡선 모양을 빌린다: e_국가(x) = e_한국(x) × e_국가(85) / e_한국(85) (같은 성별) (설계자 판단)
- 변환 스크립트는 `apps/life_balance/tool/build_life_tables.py`(Python, 원본 CSV → JSON). 원본 파일과 다운로드 URL, 조회일을 `assets/life_tables/SOURCES.md`에 기록
- 100세 초과 나이는 100세 값 사용

### 5.3 잔고 계산 (순수 함수, domain)

- 입력: 생년월일, 성별, 국가, 기대수명 수동값(nullable), 오늘 날짜(로컬 자정 기준 Date), 생명표
- 만 나이 a = 오늘 기준 만 나이
- 기준일(anchor) = 가장 최근 생일(만 a세가 된 날). 2월 29일 생은 평년에 2월 28일을 생일로 본다
- 생명표 모드: 만기일 = 기준일 + round(e(a) × 365.2425)일
  - 기획서의 "만기일 = 오늘 + 기대여명"을 "가장 최근 생일 + 기대여명"으로 바꾼 것은 설계자 판단이다. 오늘을 기준으로 하면 앱을 연 날에 따라 만기일이 달라지고 매일 재계산 시 잔고가 줄지 않는다. 생일 기준이면 1년 동안 매일 정확히 1일씩 줄고, 생일에 새 기대여명으로 갱신된다(생일에 잔고가 늘어날 수 있음, 의도된 동작)
- 수동 모드: 사용자가 기대 수명(총 수명, 년)을 직접 입력하면 만기일 = 생년월일 + 입력값(년, 날짜 연산으로 더함). 생일 갱신 없음
- 온보딩에서 보여주는 자동 산출 기대 수명 = a + e(a) (소수 1자리)
- 남은 일수 = 만기일 − 오늘 (일)
- 남은 일수 ≤ 0 이면 보너스 잔고: 경과 일수 = 오늘 − 만기일. 단위 변환은 경과 일수에 동일 적용
- 단위 표시
  - 일: 정수, 천 단위 구분
  - 주: floor(일/7), 정수
  - 년: 일/365.2425, 소수 1자리 (내림)
  - 백분율: 남은 일수 / (만기일 − 생년월일) × 100, 소수 1자리. 보너스 상태에서는 0.0%와 보너스 일수 병기
- 사용 비율(중형 위젯 진행 막대) = 1 − 백분율/100

### 5.4 만기일 일정 (위젯이 앱 없이 생일을 넘기기 위한 장치)

- 앱은 저장/설정 변경/앱 실행/자정 작업 시 향후 10년치 `[(유효시작일, 만기일)]` 목록을 계산해 위젯 저장소에 기록한다
- 위젯(Kotlin)은 오늘 날짜에 해당하는 항목을 골라 남은 일수를 계산한다. 목록이 소진되면 마지막 만기일을 그대로 쓴다
- Kotlin 쪽 계산은 "일정에서 항목 고르기 + 날짜 차이"만 한다. 생명표 조회와 단위 변환 규칙은 Dart에만 둔다. 단위별 표시 문자열은 Kotlin에서 같은 규칙으로 계산해야 하므로, 단위 변환 함수는 Kotlin에 동일하게 구현하고 Dart/Kotlin 양쪽에 같은 테스트 벡터(JSON 고정 파일)로 검증한다

### 5.5 홈 화면 위젯 (Android Glance)

- home_widget 패키지로 SharedPreferences에 기록: 일정 목록(JSON), 생년월일, 표시 단위, 말투 id, 테마 색상값, 문구 템플릿(소형 라벨, 중형 라벨, 오늘 출금 문구, 보너스 라벨)
- 소형(2x1 이상): 잔고 숫자 + 라벨
- 중형(4x2): 잔고 숫자, 오늘 출금 문구(-1일), 사용 비율 진행 막대
- Glance 텍스트는 커스텀 폰트와 font feature를 지원하지 않는다(구현 전 Glance API 문서로 재확인). 그래서 위젯 숫자는 시스템 산세리프(Roboto, 숫자 기본 고정폭)로 표시해 자릿수 흔들림을 막는다. 말투별 테마는 위젯에서 색상과 라벨 폰트 계열(스토아는 `FontFamily.Serif`, 나머지는 `SansSerif`)로만 반영한다 (설계자 판단)
- 자정 갱신: `updatePeriodMillis`(최소 30분 주기)로는 자정에 맞출 수 없으므로 WorkManager 자정 작업(5.6)이 위젯 `updateAll`을 호출한다. 추가로 `ACTION_DATE_CHANGED`, `ACTION_TIME_CHANGED`, `ACTION_TIMEZONE_CHANGED`, `BOOT_COMPLETED` 수신 시 갱신. 렌더 시 직접 계산이므로 갱신이 늦어도 다음 렌더에서 정정된다
- 위젯 탭 시 앱 메인 화면 실행

### 5.6 상시 알림

- flutter_local_notifications, `ongoing: true`, `autoCancel: false`, 낮은 중요도 채널(소리/진동 없음), 앱 아이콘
- 문구: 말투별 템플릿. 기본 형식 `인생잔고 {balance} · 오늘 -1일` (단위는 설정값 따름)
- 기본 켜짐. 온보딩 마지막 단계에서 Android 13+ 알림 권한 요청. 거부 시 설정에서 꺼진 상태로 표시하고 다시 요청 경로 제공
- 자정 갱신: workmanager 패키지 periodic(24시간) 대신 one-off 작업을 다음 자정+1분으로 예약하고, 작업 실행 시 알림/위젯 갱신 후 다음 자정 작업을 재예약. 앱 실행 시마다 예약 상태를 재확인
- Android 14+에서 사용자가 알림을 밀어 지우면, 다음 자정 작업이나 앱 실행 시 다시 표시한다(설정이 켜져 있는 경우)
- 백그라운드 isolate에서도 계산이 가능하도록 domain 계산은 Flutter 의존 없이 작성하고, 필요한 입력은 shared_preferences에서 읽는다

### 5.7 말투와 문구

- 3종: `stoic`(기본), `wit`, `community`
- 에셋: `assets/tones/{tone}.json`, 키-문장 테이블. 플레이스홀더 `{balance}`, `{unit}`, `{days}`, `{bonus}` 등
- 문구 키(최소): 메인 화면 제목/잔고 라벨/만기일 라벨/계좌 개설일 라벨/오늘 출금/보너스 잔고 안내, 위젯 소형·중형 라벨, 알림 템플릿, 온보딩 안내, 위젯 추가 안내, 카이로스 소개 문구
- 같은 키에 여러 문장을 두면 날짜 기반(일련번호 % 개수)으로 하루 하나 선택 — 매일 문구가 바뀌지만 같은 날에는 위젯/알림/앱이 같은 문장
- 커뮤니티 말투: 디시인사이드식 어휘/어미를 쓰되 혐오, 차별, 성적 표현, 특정 집단 비하는 제외. 문구 작성 후 금지어 목록 검사 테스트를 둔다(`test/tone/community_policy_test.dart`)
- UI 언어는 한국어 단일(설계자 판단: 말투 3종이 한국어 문체에 의존). 국가 목록은 11개국이지만 해외 거주 한국어 사용자를 고려한 것으로 본다

### 5.8 테마

| 말투 | 바탕 | 글씨 | 포인트 | 숫자/제목 폰트 |
|---|---|---|---|---|
| 스토아 | 아이보리 | 먹색 | 바랜 금색 | 명조 계열 |
| 위트 | 밝은 파스텔 | 진회색 | 코랄 | 둥근 고딕 계열 |
| 커뮤니티 | 흰색/연회색 | 검정 | 게시판 링크 파랑 | Pretendard |

- 본문 UI 폰트는 Pretendard. 명조/둥근 고딕은 OFL 등 앱 번들 재배포가 허용된 폰트만 쓴다(후보: 나눔명조, 나눔스퀘어라운드 — 라이선스 원문 확인 후 확정)
- 각 테마에 다크 변형을 둔다. 시스템 다크 모드를 따르고, 설정에서 라이트/다크/시스템 선택
- 잔고 숫자는 `FontFeature.tabularFigures()`
- 큰 글씨: 시스템 textScaler를 따르고 1.0~2.0 범위에서 레이아웃이 깨지지 않게 한다(위젯 테스트로 2.0 검증)
- 특정 사이트 로고, 레이아웃을 모방하지 않는다

### 5.9 화면

- 온보딩(단계형): 생년월일 → 성별 → 국가(기기 로캘 국가가 목록에 있으면 기본 선택, 없으면 한국) → 자동 산출 기대 수명 확인/수정 → 말투 선택 → 첫 잔고 표시 + 위젯 추가 안내 + 알림 권한 요청. 위젯 추가는 Android 8+ `requestPinAppWidget` 지원 시 버튼으로 바로 요청
- 메인(통장): 계좌 개설일(생년월일), 잔고(큰 숫자), 만기일, 오늘 출금 -1일, 사용 비율 막대, 하단 카이로스 소개 카드
- 설정: 생년월일/성별/국가/기대수명 수정(자동/수동 전환), 표시 단위, 말투(테마 연동), 라이트/다크/시스템, 상시 알림 켜기/끄기, 위젯 추가 안내 다시 보기, 데이터 출처 표기, 오픈소스 라이선스
- 성별 입력은 남/여 두 가지(생명표가 성별 2종). 표기는 "생명표 기준 성별"로 안내

### 5.10 카이로스 영역

- `lib/app/app_config.dart`에 `kairosStatus`(preLaunch/launched)와 `kairosUrl` 상수
- 출시 전: "알림 신청" 버튼이 외부 링크(폼 등)를 브라우저로 연다. URL 미정이면 버튼을 숨기고 소개 문구만 표시
- 출시 후: 스토어 링크로 이동

### 5.11 저장소

- shared_preferences: 프로필, 설정
- home_widget 저장소: 위젯/백그라운드 작업이 읽는 파생값(일정, 문구 템플릿, 색상)
- 프로필/설정이 바뀔 때마다 파생값을 다시 기록하고 위젯/알림 갱신을 요청하는 단일 함수(`syncDerivedOutputs`)를 둔다

### 5.12 테스트

- domain: 잔고 계산 경계값(윤년 생일, 생일 당일, 만기일 당일, 보너스 전환, 100세 초과, 수동 모드), 단위 변환, 일정 생성
- data: 생명표 JSON 파싱, 문구 테이블 파싱/플레이스홀더 치환, 저장소
- presentation: 온보딩/메인/설정 bloc 테스트, 큰 글씨 2.0 위젯 테스트
- 공통 테스트 벡터 JSON을 Dart 테스트와 Kotlin 단위 테스트(`android/app/src/test`)가 함께 사용
- 커뮤니티 말투 금지어 검사
- 실기기/에뮬레이터 수동 검증: 위젯 추가, 날짜 강제 변경 후 위젯/알림 갱신, 재부팅 후 알림 복구

## 6. 구현자에게 맡기는 것

- 위젯 레이아웃 세부(여백, 폰트 크기), 아이콘
- 문구 본문 작성(키 목록과 말투 원칙은 위 기준)
- 정확한 색상값(테마 표 기준)
- 앱 아이콘/스토어 등록 자료는 이번 범위 밖, 필요 시 별도 작업
- Play 출시 인프라(서명 키스토어, release-all CI 등록, Fastlane 업로드)는 이번 범위 밖이다. 로컬 release 빌드(`flutter build appbundle`) 성공까지만 검증한다. 등록 절차는 `doc/26_Q4/new-app-registration-flow.md`를 따라 별도 작업으로 한다 (설계자 판단)
- 국가 목록은 최신 IMF WEO 명목 GDP 순위를 그대로 따른다. 확인 결과 목록이 위와 다르면(예: 러시아 진입) 순위대로 반영한다(기획서 규칙)
