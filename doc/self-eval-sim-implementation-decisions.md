## 3. 온디바이스 모델 (명세 기능 영역 A)

### 3.1 모델 선정 (2026-11-19, 사용자 지시 "임의 모델 선택")

후보: flutter_edge_ai 모델 카탈로그(https://flutteredge.ai/docs/models) 중 Hugging Face 토큰 없이 받을 수 있는(게이트 없음) 다국어 채팅 모델. 3개 모두 Hugging Face API 로 `gated: false`, `license: apache-2.0` 확인.

| 후보 | 기기용 파일 크기 | 한국어 대사 비교 결과 (같은 프롬프트 9개, 호스트 MLX 4bit 변환본) |
| --- | --- | --- |
| Gemma 4 E2B (`litert-community/gemma-4-E2B-it-litert-lm`) | 2,588 MB | 9개 모두 지시한 언어로 대사 형태 성립. 한 문장 0.3~0.8초(M1 Pro) |
| Qwen 2.5 1.5B Instruct | 1,598 MB | 한국어가 깨지거나 지시와 무관한 문장 ("머리카락이 말라 죽었지만, 땅이 보라색인 줄 몰랐다" 등) |
| Qwen3 0.6B | 343 MB | 한국어 문장 자체가 성립하지 않음 ("내가 니의 턭을 담고 ...") |

[판단] Gemma 4 E2B. 한국어 대사가 성립한 유일한 후보. 비교는 호스트(MLX 4bit)에서 했으므로 기기용 LiteRT-LM 파일과 양자화가 다르다. 기기에서의 실제 출력은 `doc/self-eval-sim-simulation-report.md` 에 따로 기록했다.

### 3.2 연동

| 항목 | [명세] | [판단] |
| --- | --- | --- |
| 실행 라이브러리 | - | `flutter_gemma` 0.16.5. 후속 패키지 `flutter_edge_ai` 2.6.0 은 Dart 3.12/Flutter 3.44 이상을 요구하는데 저장소는 Flutter 3.41.2(Dart 3.11)라, 이 SDK 에서 쓸 수 있는 마지막 버전을 고름. 0.16.5 는 Gemma 4 `.litertlm`(ModelType.gemma4) 지원 포함 |
| 파일 | - | `gemma-4-E2B-it.litertlm` (CPU/GPU 공용판, 2,588,147,712 바이트). Hugging Face 리비전 `2d74ac4...` 로 주소를 고정 |
| 추론 장치 | 최신 플래그십 | CPU 로 고정 (`PreferredBackend.cpu`). GPU 판(2,341MB)은 기기별 GPU 드라이버 차이로 동작 보장 범위가 좁아 보류 |
| 플랫폼 제약 | iOS, Android | Android 는 arm64-v8a 전용 (x86_64 에뮬레이터 불가). iOS 는 이번 범위에서 빌드하지 않음 |
| AI 역할 3가지 | 결과 문구, 선택지 생성, 누적 해석/발현 판단 모두 고려 | (1) 개별 결과 대사: 모델 생성 (2) 누적 발현 대사: 재료(과거 선택)를 엮는 모델 생성 (3) 발현 판단: 명세의 확률 규칙을 코드로 결정 (모델에 맡기면 확률/천장 보장이 깨짐) (4) 선택지 생성: 미구현 (2절) |
| 프롬프트 | 답변 포맷은 사용자가 제공 예정 | 코드가 아니라 `assets/narration/prompts.json` 에 둠 (언어별 지시문, 줄 수, 길이 상한, 금지 패턴). 한국어는 한국어로 지시, 영/일/중은 영어로 지시하고 출력 언어만 지정. 화자 말투 예시로 채널의 기본 대사 8줄을 넣음 |
| 출력 정리 | 어투/단어/어순에서 AI 티가 나면 안 됨 | 번호/글머리표/이름표/따옴표/특수 토큰 제거, 결과 이름이 든 줄·금지 패턴 줄·길이 1.5배 초과 줄 삭제. 남은 줄이 기본 결과 2줄, 발현 2줄 미만이면 출력 전체를 버리고 템플릿으로 대체 |
| 대체 | - | 모델 실패(로드 실패, 60초 시간 초과, 규칙 미통과) 시 기본 결과는 콘텐츠 대사, 발현은 템플릿 팩. 결과마다 출처(model/template)를 기록 |
| 샘플링 | - | temperature 0.8, topK 40, topP 0.95, 사고(thinking) 모드 끔. 시드는 앱 난수에서 뽑음 |

| 요청 단위 | - | 요청마다 새 세션을 열고 닫아 이전 결과 맥락이 섞이지 않게 함. 추론은 한 번에 하나씩 순서대로 |
| 미리 불러오기 | - | 모델이 준비되면(관문 통과 직후) 백그라운드에서 모델을 메모리에 올려 첫 결과 대기를 줄임 |
| 내려받기 | 처음 실행 때. 다운로드 전 사용 불가 | flutter_gemma 다운로더 사용 (500MB 초과 파일은 Android 포그라운드 서비스, 실패 시 재시도 10회). 받기 전에 HEAD 로 크기를 확인해 상한을 넘으면 받지 않음. 서버가 크기를 안 주면 예상 크기(2,588,147,712)로 검사 |

## 5. 누적 발현 (명세 기능 영역 F)

| 항목 | [명세] | [판단] |

| 확률 표현 | 시작 0%, 시행마다 상승, 발현 시 초기화 | 천분율 정수(0~1000)로 저장해 부동소수 오차 제거 |
| 증가폭 | 10%p 이하 랜덤 | 0.1%p~10%p, 0.1%p 단위 균등 분포. 하한과 분포는 명세에 없음 |

| 재료가 없을 때 | - | 발현하지 않음(천장이어도). 확률이 0 보다 크면 과거 시행이 1건 이상 있으므로 현재 규칙에서는 일어나지 않는 방어 분기다(전체 삭제 시 확률도 0 으로 함께 초기화) |
| 발현 형태 | 섞임, 별도 연출 둘 다, 무작위 | 50:50. 섞임 = 기본 장면 대사 뒤에 이어짐. 별도 = 기본 장면 뒤 "낯선 목소리" 장면 |

## 11. 알려진 제약

- `flutter_gemma` 는 pub.dev 에서 중단(discontinued) 표시된 패키지이고 후속은 `flutter_edge_ai`. 저장소 Flutter 를 3.44 이상으로 올리면 옮겨야 한다.
- 빌드할 때 flutter_gemma 가 GitHub 릴리스에서 LiteRT-LM 네이티브 라이브러리를 내려받는다 (체크섬 검증 로그 확인). 오프라인 빌드 환경에서는 캐시(`~/Library/Caches/flutter_gemma/native`)가 필요하다.
- `flutter drive` 는 실행마다 앱을 지우고 다시 설치해 모델(2.4GB)도 지워진다. 통합 테스트마다 모델을 다시 받는다 (로컬 미러 기준 약 4.5분).
- 모델 다운로드 중 앱이 종료되면 처음부터 다시 받는다 (Hugging Face CDN 이 이어받기를 지원하지 않는다는 flutter_gemma 문서 기준).
