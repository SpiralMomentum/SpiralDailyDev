# 지출 위젯 (spend_ledger)

결제 문자를 받아 지출을 기록하는 본인용 앱이다. 이 문서는 1단계 iOS 수집 프로토타입(1~4절)과 2단계 Android 알림 수집(5절)을 실기기에서 확인하는 방법을 적는다.

## 1. 설치

1. iPhone을 Mac에 연결하고 개발자 모드를 켠다(설정 > 개인정보 보호 및 보안 > 개발자 모드).
2. `apps/spend_ledger/ios/Runner.xcworkspace`를 Xcode로 연다.
3. Runner 타깃 > Signing & Capabilities에서 Team을 `BXMP99D98Z`로 고른다. 번들 ID는 `com.spiralmomentum.spendLedger`이다.
4. 저장소 루트에서 다음을 실행한다.

   ```bash
   cd apps/spend_ledger
   flutter run --release
   ```

5. 앱이 처음 열리면 알림 권한을 허용한다. 확인 알림과 대체 알림 모두 이 권한이 필요하다.

## 2. 단축어 자동화 만들기

앱의 설정 > 단축어 설정 안내 화면과 같은 순서다.

1) 단축어 앱 → 자동화 → 새로운 자동화 → 메시지
2) 메시지 내용에 '원' 포함, '즉시 실행' 선택, '실행 시 알림' 끔
3) 동작에 '결제 문자 기록'(지출 위젯) 추가, 메시지 = 단축어 입력
4) 저장

동작 목록에 '결제 문자 기록'이 보이지 않으면 앱을 한 번 열었다 닫은 뒤 다시 찾는다.

## 3. 확인할 질문 (설계 7절)

결제 문자를 받거나, 다른 기기에서 이 iPhone으로 결제 문자 형식의 테스트 문자를 보낸다. 예:

```
[Web발신]
KB국민카드1*3*승인
홍*동님
6,500원 일시불
11/27 14:03
스타벅스
누적1,234,560원
```

각 질문에 예/아니오와 관찰한 내용을 적는다.

1. 단축어 메시지 자동화 '즉시 실행'이 현재 iOS에서 확인 창 없이 돌아가는가
2. 단축어 → App Intent 실행이 앱을 화면에 띄우지 않고 끝나는가
3. App Intent 안에서 헤드리스 FlutterEngine으로 Dart `ingestMessage`를 실행해 3초 안에 알림을 띄울 수 있는가
4. 잠금화면에서 알림 '포함' 액션이 앱을 열지 않고 DB에 반영되는가
   - (a) 앱이 백그라운드에 살아 있을 때: 앱을 열었다가 홈으로 나간 상태(또는 단축어가 막 실행된 직후)에서 확인한다.
   - (b) 강제 종료한 뒤: 앱 전환기에서 앱을 위로 밀어 종료하고, 그 뒤에 온 결제 문자의 확인 알림으로 확인한다.

질문 4는 두 경우 모두 기기를 잠근 상태에서 확인 알림을 길게 눌러 '포함'을 누른 뒤, 앱을 열어 그 거래가 확인 대기에서 빠지고 합계에 들어갔는지 본다. (a)와 (b)의 결과를 따로 적는다.

## 4. 진단 화면에서 볼 값

설정 > 수집 진단에서 단축어가 실행될 때마다 한 줄씩 기록된다(최근 20건, 최신순).

| 값 | 뜻 |
| --- | --- |
| 경로 | `headless`: 헤드리스 엔진에서 저장까지 끝남. `fallback`: 실패하거나 시간이 넘어 대체 경로로 처리됨 |
| engineMs | 단축어 실행부터 Dart 준비 신호까지. 엔진을 이미 띄워 둔 상태면 0에 가깝다 |
| dartMs | Dart에서 필터·해석·저장·알림 요청에 걸린 시간 |
| totalMs | 단축어 실행부터 처리가 끝날 때까지 전체 시간 |
| 결과 | `stored`(저장), `filtered`(필터에 걸려 저장 안 함), `ready-timeout`(10초 안에 준비 안 됨), `ingest-timeout`(15초 안에 응답 없음), `engine-run-failed`(엔진 실행 실패), `error:타입`(저장 전 오류, 예외 타입만 기록) |

질문 3의 합격 기준은 경로가 `headless`이고 `totalMs <= 3000`(NFR-02)인 것이다. 처음 실행(엔진을 새로 띄움)과 바로 이어진 두 번째 실행의 값을 따로 적는다.

경로가 `fallback`이면 "N원 결제 문자가 왔어요. 앱에서 확인해 주세요." 알림이 오고, 원문은 키체인 수신함에 보관했다가 앱을 열 때 받은 시각 그대로 저장된다. 이 경우 결과 값을 함께 공유한다.

## 5. 2단계 Android

갤럭시 기기와 삼성 메시지를 기준으로 한다. 스토어 없이 USB로 직접 설치한다.

### 5.1 설치

1. 휴대폰에서 개발자 옵션과 USB 디버깅을 켜고 Mac에 연결한다(`flutter devices`에 기기가 보여야 한다).
2. 다음을 실행한다.

   ```bash
   cd apps/spend_ledger
   flutter build apk --release
   flutter install
   ```

3. 앱이 처음 열리면 알림 권한을 허용한다. 확인 알림에 필요하다.

### 5.2 알림 접근 허용

1. 앱의 설정 화면에서 알림 접근 설정을 열거나, 휴대폰 설정 > 알림 > 고급 설정 > 기기 및 앱 알림(알림 읽기 권한)으로 간다.
2. '지출 위젯'을 켠다. 목록의 서비스 이름은 '지출 위젯 결제 알림 수집'이다.
3. 기본으로 수집하는 앱은 삼성 메시지(`com.samsung.android.messaging`)와 Google 메시지(`com.google.android.apps.messaging`)다. 카드사·은행 앱은 앱 설정에서 추가한다. 허용한 앱의 알림만 처리하고, 나머지 앱은 패키지 이름만 최근 앱 목록에 남긴다.

### 5.3 절전 예외

삼성 기기는 쓰지 않는 앱의 백그라운드 동작을 멈춰 리스너가 끊길 수 있다.

1. 설정 > 배터리 > 백그라운드 사용 제한에서 '지출 위젯'이 '절전 앱'·'깊은 절전 앱'에 있으면 빼고, '절전 예외 앱'에 넣는다.
2. 설정 > 애플리케이션 > 지출 위젯 > 배터리를 '제한 없음'으로 둔다.
3. 같은 앱 정보 화면에서 '사용하지 않는 앱 권한 삭제'(사용하지 않는 앱 자동 해제)를 끈다.

알려진 한계: 삼성 메시지에서 해당 대화방을 열어 보고 있을 때 온 문자는 알림이 게시되지 않아 수집되지 않는다.

### 5.4 확인할 질문 (설계 10.6절)

결제 문자를 받거나 다른 휴대폰에서 3절의 예와 같은 형식의 테스트 문자를 보낸다. 각 질문에 예/아니오와 관찰한 내용을 적는다.

1. 삼성 메시지 결제 문자 알림에서 원문 전체가 넘어오는가(진단의 결과가 `stored`이고 후보의 금액·가맹점이 맞는가)
2. 문자를 받은 뒤 3초 안에 확인 알림이 뜨는가(`totalMs <= 3000`, 처음과 두 번째를 따로)
3. 잠금화면에서 '포함'을 누르면 앱을 열지 않고 홈 화면 위젯(5.5절)의 합계가 바뀌는가
4. 앱을 최근 앱에서 지운 뒤, 그리고 재부팅 뒤에도 수집되는가

### 5.5 홈 위젯 추가

1. 홈 화면 빈 곳을 길게 눌러 위젯 > '지출 위젯'을 연다.
2. 소(2x2), 중(4x2), 대(4x4) 중 원하는 크기를 끌어다 놓는다. 소는 합계·예산 사용률·오늘 지출, 중은 여기에 하루 권장액과 기간·지출 진행 막대, 대는 많이 쓴 곳 3곳과 최근 거래 3건을 더 보여 준다.
3. 위젯을 누르면 앱 홈이, '확인 대기 N건'을 누르면 확인 대기 화면이 열린다. 대기가 0건이면 그 줄은 보이지 않는다.
4. 앱 설정에서 금액 숨김을 켜면 위젯의 금액은 '•••'로 보인다. 위젯 맨 아래 시각은 마지막으로 계산한 때이다.

### 5.6 진단 값 보는 법

설정 > 수집 진단에서 허용한 앱의 알림을 처리할 때마다 한 줄씩 기록된다(최근 20건, 최신순). 원문은 기록하지 않는다.

| 값 | 뜻 |
| --- | --- |
| 경로 | 항상 `listener`(알림 리스너) |
| engineMs | 알림을 받은 때부터 Dart 준비 신호 뒤 넘길 때까지. 엔진이 이미 떠 있으면 0에 가깝다. 준비 전에 실패하면 totalMs와 같다 |
| dartMs | Dart에서 중복 확인·필터·해석·저장·알림 요청에 걸린 시간. 응답이 없으면 비어 있다 |
| totalMs | 알림을 받은 때부터 처리가 끝날 때까지 전체 시간 |
| 결과 | `stored`(저장), `filtered`(필터에 걸려 저장 안 함), `seen`(10분 안에 같은 앱·같은 원문이 다시 올라와 저장 안 함), `ready-timeout`(10초 안에 엔진 준비 안 됨), `ingest-timeout`(15초 안에 응답 없음), `engine-run-failed`(엔진 실행 실패), `error:타입`(저장 전 오류, 예외 타입만 기록), `service-stopped`·`engine-discarded`(엔진을 버릴 때 넘기지 못한 요청) |

날짜가 바뀔 때 위젯 요약을 다시 계산한 기록은 결과 앞에 `refresh:`가 붙는다(예: `refresh:refreshed`, `refresh:timeout`, `refresh:ready-timeout`).

질문 2는 문자를 처음 받았을 때(엔진을 새로 띄움)와 바로 이어서 받은 두 번째의 `totalMs`를 따로 적는다. 결과가 `ready-timeout`·`ingest-timeout`·`error:...`이면 그 알림은 저장되지 않았으므로 결과 값을 함께 공유한다.
